## 核心設計原則（實用至上，拒絕華而不實）
1. **以學生實用性為最高準則**：
   - 學習資源最忌諱塞入過多浮誇修飾、炫技或看不到重點的元素。設計思考方向必須 100% 聚焦在「對學生學習與理解是否有實質幫助」，嚴禁自嗨或開發者自我標榜。
2. **嚴禁空洞口號與炫技標題**：
   - 嚴格禁止出現如「完美咬合解析版」、「啟發頓悟與空間幾何思維」等華而不實的宣傳語。
   - 所有標題、副標題與標籤皆採用嚴謹、具體、清晰的 108 課綱學科概念名稱。
3. **學習頁面專注無干擾（沉浸式學習）**：
   - 介紹導覽列（HeroBanner）與宣傳性質按鈕只允許在「首頁（未選取單元）」展示。
   - 當使用者點擊單元進入讀重點時，必須隱藏 HeroBanner，將螢幕頂部空間直接保留給章節核心筆記與附加資源，避免干擾學生學習。
4. **學科知識精準真實**：
   - 各單元重點整理必須真實對應 108 課綱該學科特色（生物著重顯微結構、生理調節；物理著重受力分析、運動圖表；數學依數A/數B切分定理與設式）。嚴禁將數學術語隨意套用於生物自然單元。
5. **閱讀動線與排版原則（垂直單欄、由上而下、先有題目再談邏輯）**：
   - **文字排版嚴禁多欄分割**：步驟解析、解題流程、常見盲點與避坑提醒等文字區塊，閱讀動線一律「由上而下垂直單欄（Single Column）」排列。嚴禁在文字內容間採用雙欄或三欄橫向並排，避免卡片過窄造成文字擠壓與閱讀跳躍。
   - **圖文排版上下優先**：函數圖形、幾何圖表與解題步驟一律採「上下垂直排列」以保有充裕橫向空間與 1:1 完整視野；唯有在文字公式極短且右側留白過多時，才可將圖置於右側。
   - **先有題目，再談邏輯（破題思維與經典題型深度整合）**：
     - 破題思維嚴禁空談抽象概念，必須「先給出具體題目範例」，讓學生先明瞭要解決的問題是什麼。
     - 破題思維與經典題型整合為統一的完整教學單元：
       `【典型範例題目】` ➔ `【核心直覺圖形 / 破題心法】` ➔ `【步驟化破題思維（步驟 1、2、3 由上而下垂直單欄）】` ➔ `【結論答案】`。
     - 解題步驟預設折疊，提供獨立開關與全區一鍵展開/收合，鼓勵學生先自行思索再對照詳解。
6. **嚴禁標註講義/課本頁碼與題號出處**：
   - 題型標題、步驟解析與教材內文嚴禁出現「講義精選」、「講義範例6」、「P95」、「P108」等實體講義頁碼或出處標籤，一律採用具學科概念的專業標準題型命名（例如「題型一：指數方程的根與圖形」、「題型三：對數律的熟用」），保持平臺教材的獨立性、原創感與專業性。
7. **章節重點頁標準格式（固定五大區塊，依序呈現）**：
   1. **核心觀念與公式精要**（`coreConcepts`）
   2. **經典題型與破題核心**（`sopModules`；題目 ➔ 破題心法 ➔ 折疊步驟 ➔ 結論答案）
   3. **常見解題盲點與避坑提醒**（`pitfalls`）
   4. **自我挑戰**（`quizQuestions`）
   5. **本單元實戰補充資源**（`resources.ts` 對應資源）
   - 「經典範例」與「破題思維」本質相同，不得再拆成兩個區塊。新增內容一律寫入 `sopModules`，不再新增 `classicExamples`（舊資料於渲染時自動併入第 2 區塊）。
8. **數學式一律以 KaTeX 排版**：
   - 內文、圖例、圖下說明中的數學式一律以 `$...$` / `$$...$$` 交由 `renderRichMathText` 渲染，嚴禁直接以純文字或 Unicode 符號（如 ⟹、−、/ 分數）拼湊數學式。
   - 函數圖（`FunctionGraph`）上的點標籤與數學註記使用 `latex` 欄位（KaTeX 渲染），不使用純文字 `label`；純註記可搭配 `hideMarker: true`。
   - 圖上點標籤應以「題目給定條件」標記（如 $P(a,\ b+2)$、中點 $M\left(\frac{P_x+Q_x}{2},\ \frac{P_y+Q_y}{2}\right)$），不得直接標出答案數值。

## 自主更新標準作業流程（SOP）
當使用者要求新增教材、試卷或調整內容時，助理自主完成下列流程：
1. **靜態資源存放**：
   - 動態 3D / HTML5 模擬檔 ➜ `public/simulations/`
   - 題目卷與解析卷 PDF ➜ `public/papers/`
2. **資料庫登記**：
   - 於 `src/data/resources.ts` 依據 108 課綱單元格式登記（含標籤、Aha! 頓悟提示與學習目標）。
3. **驗證建置**：
   - 執行 `npm run build` 確認無任何語法或型別錯誤。
4. **自動推播與即時發布**：
   - 於 `D:\Google 雲端硬碟\AhaZone` 執行：
     ```bash
     git add .
     git commit -m "<清晰的繁體中文更新說明>"
     git push origin main
     ```
   - GitHub 收到推播後會自動通知 Vercel CI/CD 即時重新建置並部署至 `https://aha-zone.vercel.app`。
   - 若需手動強制觸發或查詢狀態，可讀取 `.env.local` 中的 `VERCEL_TOKEN` 呼叫 Vercel REST API。
